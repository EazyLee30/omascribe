Meetings now support multiple separate recordings, with direct access to audio and transcript files. Local writing uses streaming responses and visible progress so slower generation can complete without the previous fixed 180-second request timeout.

- **Multiple takes:** Finish the current take, then record another in the same meeting, including after restarting. Earlier audio, transcript corrections and note citations are preserved. Pause/resume continues the current take.
- **Meeting files:** Browse numbered WAV recordings, per-take text transcripts and the complete Markdown transcript. Reveal a file or open the meeting folder in your file manager. Transcripts synchronize automatically.
- **Local writer:** Loading/reading/writing phases, elapsed time, bounded streaming reads, an overall watchdog, memory-aware deferral and retry backoff. Incomplete or interrupted output cannot replace saved minutes or advance coverage.
- **Retranscription:** Recognition resets at each take boundary, keeping text aligned with individual WAV files.
- **English, Simplified Chinese and Traditional Chinese** UI copy and READMEs updated, with an actual file-panel screenshot.

Validated on the target 2016 Intel MacBook: 12 Rust tests, two Python harness tests, 11 native Tauri/WebKit flow checks, and a public-speech test covering sample-exact append across restart, preserved corrections and boundary-aware retranscription. Under an observed 800 MHz power-saving state, the fictional automatic document task completed in about 193 seconds with all three progress phases visible. This is a functional regression result, not a general speed or accuracy guarantee.

Source release for x86-64 Linux / Omarchy. Existing models and inference runtime remain compatible. Update the source, run `bin/build`, then `bin/install`. Meeting storage is migrated additively; original PCM and SQLite remain authoritative.
