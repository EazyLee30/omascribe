# 0.3.5 发布收敛清单

这是三端共用的唯一发布阻塞清单。原始报告按来源提交保留；日常只更新问题、负责人、验证结果与下一步。整体资源优化研究继续推进，单个小版本不等待全部研究完成。

## 范围与当前候选

0.3.5 优先解决生产转写与纪要的预算更正、否定/撤回状态、无依据补写、字幕翻译收尾，以及三端实际阻塞安装、启动、录音、停止或升级的问题。差分更新、完整说话人重构、新模型与新后端独立推进。

**候选 5：`6498696ca75ad60d20e06b52e20cc7f084e707a0`**，固定分支 `codex/release-0.3.5-candidate-5`。Mac 同一干净编译来源的完整 32 项自动双语链路 **32/32 通过**，已核对全部最终正文及引用，并用原始日志确认 43 轮均实际 Metal offload；另完成四次公开 PCM 的实际 Engine 回放并发/收尾检查。**尚未放行或打包**；自然录音质量、三端原生与安装升级仍需同一候选验收。

本地同源检查：core **176 通过/7 忽略**、ASR **5 通过**、desktop **4 通过**、Python **65 项/1 跳过**，workspace 及 native ui-test 全 targets 严格 clippy 通过。[本轮原始输出、来源哈希、分阶段失败与限制](../evaluation/apple-candidate5-caption-finalization-2026-10-28.json)。重复/含混原文的文章仍不够精炼，个别译词生硬；不能把这套文本检查当自然语音识别准确率或完整翻译质量验收。

五项候选 4 失败已在生产链路修复：专名修正使用 JSON 安全约束与前置单一姓名锚定；字面数字读法保留同一数字序列；孤立连接词/中性语气词避免生成，保留显式词库优先级；更正后的期限句保留负责人拼写；无主语的“预算……但仍未通过”接回批准主题，不能借用“测试未通过”。输出耗尽只保留待处理内容，避免误判 GPU 传输故障后整批 CPU 重跑。原文/人工段落不覆盖，8 次批次上限、同片段至多一次批内修正及录音期 8 秒预算不增加，模型、SDK 和组件不改。

候选 4 `63eefa3` 的 27/32 失败来源及固定分支保持不动，[旧机器证据](../evaluation/apple-caption-source-spellings-2026-10-27.json)保留。0d22a0b 的 5/7、84037ff 的 6/7 受影响检查及其原失败也保留；本次 32/32 全部来自候选 5，同一 CLI、语料、配置与推理源码，未拼接不同版本。

## 交付节奏与分工

- 主线程负责共享转写/翻译/纪要、事实校验、Mac Metal、集成和候选冻结；Windows 负责本端输入/停止、冷 ASR、CUDA 与回退；Linux 负责本端桌面/音频和 Omarchy。共享契约变更先在 PR 给最小差异，避免重复修改同一模块。
- 小修通过受影响检查立即推源码、提最小 PR，即审即集成；不等全部研究结束。正在验证的固定提交继续完成，不为文档 head 或无关变化重启同一轮。
- 开发期只跑受影响回归。主线程修复已知共享阻塞并冻结下一 SHA 后，三端围绕同一版本完成完整语料、真实录音及必要原生验收；最后统一构建候选安装/更新包并验升级。
- 复用已签 GPU 组件、模型和 SDK；组件有缺陷才重建/重签。Windows 优先复用已验证 CUDA 跑候选完整语料，CPU 补受影响和回退检查，避免无依据重复完整 CPU×GPU 矩阵。
- 平台没有实际发布阻塞时直接回报“无新增阻塞”，保留已有来源证据；体验优化和研究移入后续小版本。失败和未测如实登记，保持原始起点、PCM、延迟门、事实门和重试预算。
- 交付只报 **问题 ID—负责人—提交 SHA—验证结果—下一阻塞**。有交付、失败变化或必要用户动作才更新；不重复长报告和无变化 CI 播报。
- 发布时间在下一候选完整回归后重新估算。0.3.5 发布不代表全部优化研究结束。
