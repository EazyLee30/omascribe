### Incremental terminology and translation cache follow-up

- Core regression suite: 85 passed, 3 opt-in tests ignored; workspace clippy passed. Added a persistent revision queue instead of scanning all previous passages on every final ASR event. Reads are bounded to 128 records, acknowledgement cannot remove newer work, and the v5 migration backfills existing current-run passages. Human text remains protected. Disabling a term or hiding/restoring a linked note reevaluates automatic corrections against the archived original.
- Translation cache keys now include meeting/run, complete source revision/text and speaker bindings, target, model catalog hashes/file metadata, runtime binary hash, optional component binding, prompt/schema and execution configuration/permissions. Older cache rows recompute once. Runtime hashes use a bounded metadata cache; large model weights are not rehashed by each UI snapshot. Deleted meetings clear these derived caches transactionally while preserving recoverable source/notes.
- Real installed Qwen3-1.7B translation harness passed two invented Chinese/English passages (negation and weekday), unchanged originals and four display modes. Repeating the same request added no worker trace. This is a narrow regression check, not overall ASR/translation throughput evidence.

### Resumable translation and component packaging follow-up

- Each translation unit is bounded by the runtime tokenizer to 256 input tokens (system instruction included), reserves output/template headroom and uses at most eight generation requests per batch. Recording yields between chunks after its time allowance; the existing worker monitor can interrupt sooner for ASR lag or memory pressure. This is not a hard eight-second completion guarantee for an individual model request.
- A persistent turn rotates the selected oldest/newest sources even after cancellation or failure. Long sources save private revision/config-bound progress in SQLite and become visible only when complete. Source edits and deletion clear private chunks; final translation and chunk removal commit together. Invalid answers defer that passage while other selected work proceeds. No multi-item combined generation/default model promotion is claimed.
- Initial real-model testing exposed a preexisting misuse of the minutes validator's 1,200-character paragraph limit for translations. Translation now has a separate 16,000-character ceiling and supports source lists, while retaining numeric/date/uncertainty guardrails. Minutes keep the original prose/length rules. The synthetic failure evidence is retained locally in ignored `artifacts/benchmarks/translation-chunks-failure`.
- Rust 1.99 core suite: 88 passed / 3 opt-in ignored; workspace clippy passed on the CI compiler version. Python harness/packaging suites: 15 passed. CI's needless-borrow lint was fixed without suppressing warnings.

The short captions completed in the first batch, the long translation resumed privately, originals stayed unchanged, and amount 3000/Thursday/Friday/negation checks passed.
